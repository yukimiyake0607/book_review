# ADR-0003: レビュー永続化に shared_preferences

- ステータス: Accepted
- 日付: 2026-07-28
- 更新: 2026-07-31（Issue #15 / ADR-0008 により「キャッシュ」から「単一の情報源」へ前提を更新）
- 更新: 2026-08-03（上記の前提変更に名前を追随させ、`ReviewLocalCache` を `ReviewLocalStore` へ改名）

## コンテキスト

本アプリのレビューデータは**単一ユーザーのレビュー一覧**という小さく単純な構造で、
複雑なクエリ・リレーション・全文検索は要件にない（スコープ外、要件定義 §2.3）。

当初はサーバ CRUD の補助キャッシュとしてローカル保存を想定していたが、
OpenAPI / サーバ同期を廃止したため（ADR-0006 → ADR-0008）、ローカルが永続化の本体になった。

## 決定

**`shared_preferences` にレビュー一覧を DTO の JSON 配列として保存し、これを単一の情報源（SoT）とする。**

- 保存/読み出しは [`ReviewLocalStore`](../../lib/src/features/reviews/infrastructure/review_local_store.dart) に閉じ込める
- 壊れたデータは黙って破棄し、空一覧として扱う
- ストレージキーにバージョン（`review_v1`）を含め、将来のフォーマット変更に備える
- 名前は Store とする。Cache だと「失っても正本から戻せる控え」に読めるが、実際はここが正本であり、消えたらデータは戻らない

## 検討した代替案

### a. drift（SQLite）
リレーショナルなクエリ・リアクティブな監視・マイグレーションを備え、設計力の見せ場も大きい。
しかし本アプリのローカルデータ要件（1リストの読み書き）に対しては明確に過剰で、
スキーマ定義・生成・マイグレーションの運用コストが便益を上回る。
**「規模に見合う技術選定をする」判断として却下**（過剰設計の回避。ADR-0002 と同じ姿勢）。
将来、フィルタ/ソートや統計（要件 §2.2 の Should）を本格化する場合の第一候補として残す。

### b. 永続化しない（メモリのみ）
実装は最小だが、再起動でレビューが消える。デモの DoD（登録 → 一覧反映の継続）を満たせない。却下。

## 結果（トレードオフ）

- 得たもの: 依存とコードの最小化、オフラインでも完結する CRUD、モックサーバ不要の実行
- 諦めたもの: リアクティブなローカルクエリ、複数端末同期
- 関連: 更新フローは楽観的更新を使わず書き込み完了後に反映する（ADR-0008 方針B）
