# ADR-0009: APIキー不要のデモモード

- ステータス: Accepted
- 日付: 2026-08-02
- 関連: ADR-0002（レイヤードアーキテクチャ）、ADR-0008（Google Books 採用）

## コンテキスト

ADR-0008 は「モックサーバ無しで clone → run」をデモの DoD に置いた。しかし書籍検索だけはこれを満たせていない。

- Google Books はキー無しでも呼べる（`dio` のクエリにキーを付けない実装になっている）が、共有クォータが枯渇しており実際には 429 が返る
- そのためリポジトリを見た人は、Google Cloud でプロジェクト作成 → Books API 有効化 → キー発行 → ローカル配置、を済ませないと検索を触れない

このアプリを読む相手（採用担当・レビュアー）にとって、キー発行は「触るのをやめる」十分な理由になる。設計を見てもらうためのリポジトリで、入口の摩擦が最大になっている状態は目的と矛盾する。

## 決定

`Flavor.demo` を追加し、**書籍検索のみ**を同梱データで動かす。

- 既定のエントリポイント `lib/main.dart` はデモモードで起動する。`flutter run` だけで全画面を触れる
- 実 API を叩く `main_dev.dart` / `main_prod.dart` は従来どおり残す（キーを持つ人向け）
- `DemoBookRepository` は domain の `BookRepository` を実装し、同梱した Google Books のレスポンス（`assets/demo/google_books_volumes.json`）を実 API と同じ DTO / mapper で `Book` に変換する
- 差し替えは `bookRepositoryProvider` の中だけで行う。application / presentation はどちらの実装が供給されるか知らない
- レビューの永続化（`shared_preferences`）はデモモードでも本物を使う。ローカル完結でありキーも要らないため、偽装する理由がない

同梱データは実際の Google Books レスポンスから必要フィールドだけを残したもので、フォーマットは実 API と同一である。

## 検討した代替案

### a. 現状維持（キーを各自で用意してもらう）

入口の摩擦が大きく、スクリーンショットと動画しか見てもらえない。DoD とも矛盾するため却下。

### b. キーを持つプロキシサーバを立てる

実ネットワークのまま clone → run を実現できるが、可用性・費用・誰でも叩ける口を晒すリスクを負う。本リポジトリの主題（アーキテクチャと状態設計）から外れる運用コストのため却下。

### c. 制限付きの APIキーをリポジトリにコミットする

シークレットスキャンの検出対象であり、失効・悪用のリスクを負う。却下。

### d. キー不要の別 API（openBD / 国立国会図書館サーチ）へ乗り換える

ADR-0008 の比較のとおり、キーワード検索と書影の観点で Google Books を上回らない。検索体験を落としてまでキー不要を取る判断はしない。

## 結果（トレードオフ）

- 得たもの: clone 直後に全機能を触れる導線、リポジトリ差し替えという依存性逆転の実演、キー漏洩リスクのない既定経路
- 諦めたもの: 既定経路では実ネットワークの挙動（通信エラー・レイテンシ）を体験できない。実 API を見たい人は `main_dev.dart` を使う
- 同梱データの鮮度は追随しない（書影 URL が失効した場合は `_Thumbnail` のフォールバックで表示される）
