# ADR-0005: GitHub Actions による品質ゲート

- ステータス: Accepted
- 日付: 2026-07-28

## コンテキスト

個人開発でも実務同様、「壊れたコードを main に入れない」仕組みを機械化したい。
また、生成コード（freezed / json_serializable）はリポジトリにコミットしない方針
（ADR-0006）のため、CI 上で再生成してから検査する必要がある。

## 決定

**GitHub Actions で `analyze → format → test → build` の順にチェックする
`analyze / format / test / build` ジョブを、main ブランチの必須ステータスチェックに指定する。**

「CI を用意する」だけでは品質ゲートにならない。ワークフローが赤でもマージできてしまうためである。
main の branch ruleset に上記ジョブ名を required status check として登録し、
**通過しなければマージできない**状態を設定側でも担保する。

パイプライン（[.github/workflows/ci.yml](../../.github/workflows/ci.yml)）:

1. `flutter pub get`
2. `dart run build_runner build`（生成物を作る。依存は `^2.15.1` に固定。`--delete-conflicting-outputs` は 2.15 の `build` サブコマンドから廃止され、衝突は自動解決されるようになったため付けない）
3. `flutter analyze`（`analysis_options.yaml` の厳格ルール + `riverpod_lint`）
4. `dart format --set-exit-if-changed`（対象は `git ls-files '*.dart'` = 生成物を除外）
5. `flutter test`（API はモックに差し替え、ネットワーク非依存）
6. `flutter build apk --debug`（ビルド可能性の担保。ubuntu ランナーで高速）

### Riverpod 固有の規約を独立ステップにしない理由

当初は `dart run custom_lint` を独立したステップとして持っていたが、これは**常に成功する空振りのステップ**だった。
`riverpod_lint` 3.1.0 は `custom_lint` から `analysis_server_plugin` へ実装を移しており、
`custom_lint_builder` に依存しなくなっている。`custom_lint` はその `custom_lint_builder` への依存を手がかりに
プラグインを探すため、この構成では登録されるプラグインが 0 個になる。
実際、意図的に `notifier_extends` 違反を書いても `dart run custom_lint` は `No issues found!` を返した。

そこで `analysis_options.yaml` のトップレベル `plugins` で `riverpod_lint` を登録し、
`flutter analyze` に相乗りさせる方式へ移行した。同じ違反が
`warning • Notifiers must extend the correct class • notifier_extends` として検出されることを確認している。
ステップ数も減り、「lint が動いているつもりで動いていない」状態を作らずに済む。

## 検討した代替案

### a. 生成コードをコミットして CI では生成しない
CI は速くなるが、生成物のレビュー・コンフリクトが発生し差分が汚れる。
「再生成できること」を CI で保証する方が健全と判断（ADR-0006）。

### b. iOS ビルドも CI に含める
macOS ランナーが必要で低速・不安定（署名の考慮も要る）。
ビルド可能性の担保は Android APK で足りるため、iOS は CI 対象外とし、ローカル確認に委ねる。

## 結果（トレードオフ）

- 得たもの: main の常時グリーン、生成物の再現性、フォーマット/静的解析の機械的強制。
  必須ステータスチェックの指定により、ワークフローの成否とマージ可否が一致する
- 諦めたもの: CI 時間（毎回 build_runner を回すぶん増える）、iOS ビルドの自動検証。
  `riverpod_lint` をアナライザプラグインとして動かすぶん `flutter analyze` 自体は数秒遅くなる
- 注意点: 必須ステータスチェックはジョブ名で紐付くため、`ci.yml` の `name:` を変えたら
  ruleset 側も同時に更新する。片方だけ変えると「必須チェックが永久に来ない」状態になる
