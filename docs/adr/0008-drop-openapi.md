# ADR-0008: OpenAPI 廃止と公開 API + ローカルへの移行

- ステータス: Accepted
- 日付: 2026-07-29
- 関連: [ADR-0006](0006-schema-driven.md)（Superseded）, [ADR-0007](0007-error-handling.md)

## コンテキスト

[ADR-0006](0006-schema-driven.md) では OpenAPI をスキーマ駆動の SSoT とし、`swagger_parser`
でクライアントを生成、`Prism` モックに対して開発する構成を採った。運用してみて次の課題が出た。

- 題材（読書レビュー）に対して重厚で、「機能が少ないのに過剰では」という印象を与えやすい。
- 実在のバックエンドが無く Prism モック依存のため、「単体で動くアプリ」としては弱い。
- OpenAPI スキーマ駆動は実務案件でこそ実演でき、そちらでアピールできる（役割分担）。

このリポジトリの目的は「設計・アーキテクチャの提示」であり、上記を踏まえると
OpenAPI をこのリポジトリの主役から外した方が目的に合う。

## 決定

**OpenAPI / Prism / 生成クライアント（`lib/src/api/**`）を廃止する。**
データ取得元を次のように置き換える。

- 書籍検索: 実在の公開書籍 API を、**手書きの dio クライアント + mapper** で叩く（コード生成に非依存）。
- レビュー: **shared_preferences を単一の情報源**とするローカル永続化（[ADR-0003](0003-local-cache.md)）。

移行は段階を分け、常に analyze / CI が green な状態を保つ。

- **#12（本 ADR / 地ならし）**: OpenAPI 生成物・設定・参照を削除。壊れる infrastructure は
  `UnimplementedError` のスタブ + `TODO(#15)` に置き換え、コンパイル可能な状態を維持する。
- **#15（移行の実装）**: 公開書籍 API の手書きクライアントと、レビューのローカル永続化を実装する。

## 影響（エラー設計の再フレーム）

レビューがローカル化することで、「サーバ書き込み失敗 → 楽観的更新のロールバック」という
[ADR-0007](0007-error-handling.md) の自然な題材を失う。そこでエラー設計の役割を次のように整理する。

- **書籍検索（主役）**: 実ネットワーク由来の失敗を `AsyncValue`（loading / error / empty / data）で
  そのまま UI に表し、失敗は sealed な `AppException` へ変換して網羅的に分岐する。
- **レビューの保存 / 削除**: `shared_preferences` への書き込みは信頼でき「サーバ書き込み失敗」に
  相当する自然な失敗が無い。よって**楽観的更新とロールバックは廃止**し、書き込み完了後に
  一覧へ反映する（保存中は待つ）方式へ簡略化する。

この方針に伴う実コードの撤去（`ReviewListController` の楽観的更新 / ロールバック）と
[ADR-0007](0007-error-handling.md) 本文の更新は #15 で行う（#12 はデータ層をスタブ化するのみで、
既存のコントローラは現状のまま残している）。

## 検討した代替案

### a. OpenAPI を残す
実務で使う技術を示せる利点はあるが、本題材では過剰に見えやすく、モック依存で
「動くアプリ」としても弱い。同じアピールは実務案件のリポジトリで担保できるため却下。

### b. バックエンドを自作する
「動くアプリ」にはなるが、本リポジトリの目的（設計の提示）から外れ、スコープも肥大化する。却下。

### c. レビューもリモート API 化する
バックエンド不在という本質的な問題が残る。ローカル永続化で要件（自分の読書記録）は満たせるため却下。

## 結果（トレードオフ）

- 得たもの: 題材に見合った軽さ、モック無しで単体起動できる実アプリ、
  実ネットワークを題材にしたエラー設計の実演。
- 諦めたもの: スキーマ駆動 / コード生成の実演（実務案件のリポジトリで担保）、
  楽観的更新 / ロールバックの題材（レビューでは廃止し、エラー設計は検索のネットワークへ集約）。
