# ADR-0004: ルーティングに go_router

- ステータス: Accepted
- 日付: 2026-07-28

## コンテキスト

一覧 → 詳細、検索という素直な画面遷移が必要。将来、認証を導入する場合の
リダイレクトや、ディープリンクにも対応できる余地を残したい。

## 決定

**`go_router` を採用し、ルーター定義を `goRouterProvider`（Riverpod の `Provider`）で供給する。**
遷移先パスは `AppRoute` に集約し、文字列リテラルの散在を防ぐ。

Riverpod 管理下に置くことで、将来 `redirect` に認証状態などの Provider を
参照させる拡張が、ルーター定義を差し替えずに行える。この拡張余地を実際にどう使うかは
[ADR-0010](0010-auth-strategy.md) で具体化している。

## 画面へのデータの渡し方（`extra` の使いどころ）

**`extra` は URL から復元できない値にだけ使い、URL に id があるなら画面が自分で引き直す。**

`GoRouterState.extra` は `Object?` で、URL には乗らず、ディープリンクや
プロセス再生成の後には復元されない。したがって `extra` を前提にした画面は
「アプリ内から遷移したときだけ動く画面」になる。

| ルート | 渡し方 | 理由 |
|---|---|---|
| `/reviews/:id` | URL の `id` | 端末内に永続化済みで、id から引ける |
| `/reviews/:id/edit` | URL の `id` | 同上。`extra` で `Review` を運ぶと直接開いたとき編集対象を失う |
| `/reviews/new` | `extra` の `Book` | 検索結果は永続化しておらず、id だけでは復元できない |

`extra` が必要な `/reviews/new` でも、受け取りは `as Book?` ではなく `is Book` で確かめる。
素のキャストは型不一致を `TypeError`（`Error` 系）にしてしまい、外部から与えられた値で
「コードのバグ」扱いのクラッシュを起こすため（ADR-0007）。値が無い場合と未定義パスは
どちらもホームへの導線を持つ画面へ集約し、行き止まりを作らない（`errorBuilder`）。

画面が必要とするデータを自分で持たない場合は「入口 Widget が id から解決し、
解決済みの値をフォームへ渡す」形にする（`ReviewEditorLoader` → `ReviewEditorScreen.edit`）。
フォーム側は `flutter_hooks` で初期値を組み立てるため、読み込み前に構築すると
初期値が空のまま固定される。解決を1段外に出すことでこれを避けている。

## 検討した代替案

### a. Navigator 1.0（`Navigator.push`）
宣言的でなく、ディープリンク・リダイレクトの拡張が煩雑。却下。

### b. auto_route
コード生成前提であり、本リポジトリはコード生成の依存を
freezed / json_serializable に限定する方針（ADR-0001）。追加の生成器を増やさないため却下。

### c. Beamer 等
go_router が Flutter 公式推奨であり、情報量・保守性で優位。

## 結果（トレードオフ）

- 得たもの: 宣言的ルーティング、認証リダイレクト拡張の余地、URL だけで開けるディープリンク
- 諦めたもの: auto_route のような型付きルート引数（`AppRoute` の薄いヘルパで代替）。
  `extra` は `Object?` のままなので、受け取り側の型チェックは自前で書く必要がある
