# ADR-0008: 書籍検索APIの検討

- ステータス: Accepted
- 日付: 2026-07-29

## コンテキスト

書籍のレビューを登録するには、書籍の情報を取得しなければならない。そこで、書籍を検索できる公開APIを選定する。

## 決定

使用する書籍検索APIを「Google Books」とします。

このアプリではログイン機能がないためトークンがありません。よってOAuthが必要な検索APIは使用できません。
しかし検討したAPIはすべて不要でした。決定した差はそこではなく、このアプリの「書籍を検索してレビューする」動線に合うかを軸としました。

| | Google Books |openBD | 国立国会図書館サーチ |
| ---- | ---- | ---- | ---- |
| タイトル/キーワード検索 | ある |ない |ある |
| ユーザーログイン | 不要 |不要 |不要 |
| アプリ側の識別 | APIキー推奨/事実上必要 |不要 |不要 |
| 書影 | ある |ある |終了 |
| レスポンス | JSON |JSON |XML寄り |

「Google Books」では
1. 検索UXが向上する
レビューアプリでは「タイトルで探す」が主導線。openBDはISBN lookupなので、検索機能の題材として弱い。

2. ユーザートークン不要
必要なのはアプリ識別用の APIキー（.env 等）。ログイン機能とは別物で、今のアプリ構成と矛盾しない。

3. ポートフォリオの見せ場と相性がいい
実ネットワーク・JSON・mapper・書影・失敗時の sealed error を一通り見せやすい。NDLは書影API終了済みでUIが弱く、XMLパースのコストも増える。

## 検討した代替案

### a. openBD
キー不要で魅力的ではあるが、キーワード検索できないので「書籍検索」APIとして不適。

### b. 国立国会図書館サーチ
キー不要・タイトル検索可だが、書影が使えず、レスポンスも扱いづらい。非ログインの利点だけでは Google Books を上回らない。

## 結果（トレードオフ）

キーは必要になるが、その他の面で優れているため「Google Books」で問題ないと判断。
