# ADR-0008: OpenAPI 廃止後の公開 API＋ローカル永続化

- ステータス: Accepted
- 日付: 2026-07-29
- 関連: ADR-0006（Superseded）、Issue #12（地ならし）、Issue #15（実装）

## コンテキスト

ADR-0006 の OpenAPI スキーマ駆動（swagger_parser + Prism）を廃止した（#12）。
残ったスタブを、**実データ層**に置き換える必要がある（#15）。

置き換えの軸は次の3点である。

1. 書籍検索の公開 API 選定
2. レビューの永続化先（サーバ CRUD の代替）
3. エラー／更新方針の再整理（検索はネットワーク、レビューはローカル）

## 決定

### 1. 書籍検索 API は Google Books

| | Google Books | openBD | 国立国会図書館サーチ |
| ---- | ---- | ---- | ---- |
| タイトル/キーワード検索 | ある | ない | ある |
| ユーザーログイン | 不要 | 不要 | 不要 |
| アプリ側の識別 | APIキー推奨/事実上必要 | 不要 | 不要 |
| 書影 | ある | ある | 終了 |
| レスポンス | JSON | JSON | XML寄り |

採用理由:

1. **検索UX** — レビューアプリの主導線は「タイトルで探す」。openBD は ISBN lookup が中心で題材として弱い
2. **ユーザートークン不要** — 必要なのはアプリ識別用の APIキー（`dart-define` / ローカル JSON）。ログイン機能とは別物
3. **ポートフォリオの見せ場** — 実ネットワーク・JSON・DTO/mapper・書影・sealed error を一通り見せやすい

実装方針:

- 手書きの `dio` クライアント + Freezed DTO + `toDomain()` mapper（コード生成クライアントに依存しない）
- APIキーはリポジトリに直書きせず、`--dart-define-from-file=dart_defines.json` で注入する

### 2. レビューは shared_preferences を単一の情報源にする

サーバ CRUD を廃止したため、レビューの SoT（Source of Truth）は端末内の `shared_preferences` とする。

- 保存形式は DTO の JSON 配列（[`ReviewLocalCache`](../../lib/src/features/reviews/infrastructure/review_local_cache.dart)）
- 壊れたデータは黙って破棄する
- ADR-0003 の「サーバが SoT・ローカルはキャッシュ」という前提は、本決定で上書きする

### 3. エラー設計の再整理（方針B）

| 領域 | 方針 |
|---|---|
| 書籍検索 | `AsyncValue`（loading / error / empty / data）で状態をそのまま表示。失敗は sealed `AppException` で網羅分岐（エラー設計の主役） |
| レビューの保存・削除 | **楽観的更新・ロールバックを廃止**。`shared_preferences` への書き込み完了後に一覧へ反映する（保存中は待つ） |

方針Bを選んだ理由:

- レビューはローカル書き込みでレイテンシが小さく、「先にUIを動かす」必然性が薄い
- 仮ID差し込みとロールバックは、ローカル SoT では複雑さに見合わない
- 検索側のネットワーク失敗を sealed + `AsyncValue` で示す方が、本リポジトリのアピール（状態・エラー設計）に直結する

## 検討した代替案

### a. openBD / 国立国会図書館サーチ（検索API）

上記比較のとおり。キーワード検索または書影の観点で Google Books を上回らない。

### b. レビューもリモート API のまま

OpenAPI 廃止後に自前サーバはスコープ外。デモの DoD（モックサーバ無しで clone → run）と合わない。却下。

### c. レビューでも楽観的更新を維持（方針A）

サーバ往復が遅い前提では有効だが、ローカル永続化では便益が小さく、失敗時ロールバックのコードが残る。却下（方針B）。

## 結果（トレードオフ）

- 得たもの: モックサーバ不要の実行、検索の実ネットワーク題材、レビュー更新フローの単純化
- 諦めたもの: 複数端末同期、サーバ側のレビュー共有、楽観的更新による体感速度の演出
- 追随更新: ADR-0007（楽観的更新の記述）、ADR-0003（SoT の前提）、`.cursor/rules/presentation.mdc`
